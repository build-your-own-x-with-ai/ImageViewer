# PNM 格式剖析（PBM / PGM / PPM）

对应实现：`lib/src/codecs/pnm/`

## 为什么从它开始

PNM 是最简单的图像格式：没有压缩、没有调色板、头部是纯文本。所以它适合作为第一个动手实现的格式 —— 能完整走通「字节流 → RGBA」全流程，又不被熵编码干扰。

它还有第二个身份：**参照解码器**。一旦 PNM 被手写字节测试彻底验证，就能用它校验其它格式（把真实 PNG/JPEG 用系统工具转成 PPM 存进仓库当期望值）。详见 `docs/testing.md`。

## 六种变体

```
          ASCII   二进制    每像素样本数    有 maxval？
位图 PBM    P1      P4        1（1 位）        无
灰度 PGM    P2      P5        1                有
彩色 PPM    P3      P6        3                有
```

命名来自 Netpbm 工具集。魔数就是 `P` 加一个数字，是所有格式里最朴素的。

## 头部结构

```
P6                    ← 魔数
# 这是注释             ← 可选，可出现在任意 token 之间
4 4                   ← 宽 高
255                   ← maxval（P1/P4 没有这一项）
<像素数据紧随其后>
```

token 之间可以是任意空白（空格、制表、换行、回车、垂直制表、换页）。`#` 起的注释到行尾结束，可以插在任意两个 token 之间 —— 包括宽和高之间。

## 三个容易写错的地方

### 1. 位图的颜色是反的

P1/P4 里 **`1` 表示黑，`0` 表示白**，与直觉相反。

原因在于 PBM 的出身：它描述的是「哪里要落墨」（ink coverage），而不是「哪里是亮的」。打印机视角，不是屏幕视角。

### 2. 二进制变体的头部分界只有一个空白

规范规定最后一个头部 token 之后**恰好一个**空白字符是分界，之后的字节全部是像素数据。

不能像处理 ASCII 那样「跳过所有空白」。如果像素数据的首字节正好是 `0x20`（空格）或 `0x0A`（换行），跳过它就会把整幅图错位一个字节。

对应测试：`test/codecs/pnm_test.dart` 里「首像素恰是空格的字节值」那一条，专门盯这个坑。

### 3. P4 每行按字节对齐

P4 把像素打包成位，**每行独立对齐到字节边界**：

```
宽 12 → 每行 (12+7)/8 = 2 字节（12 位数据 + 4 位填充）
宽  3 → 每行 1 字节（3 位数据 + 5 位填充）
```

行对齐算错的话第一行还对，第二行开始整个错位。P5/P6 没有这个问题（它们每样本至少占一字节）。

## maxval 与缩放

maxval 不一定是 255。规范允许 1..65535 的任意值，`maxval 100` 完全合法。所以必须按比例缩放而不是简单移位：

```dart
scaled = (sample * 255 + maxval / 2) / maxval    // 四舍五入
```

maxval > 255 时二进制变体的每个样本占 **2 字节大端**。

三条特化路径：

| maxval | 处理 |
|---|---|
| 255 | 直通，不缩放 |
| 1 | 二值化：0→0，1→255 |
| 其它 | 按上式比例缩放 |

## 字节级实例

一张 2×1 的红蓝图，P6 格式：

```
50 36 0A 32 20 31 0A 32 35 35 0A FF 00 00 00 00 FF
P  6  \n 2     1  \n 2  5  5  \n ├─红──┤ ├─蓝──┤
└头─────────────────────────┘└像素数据─────────┘
                          ↑
                    这个 \n 是分界，只能吃掉一个
```

同一张图的 P3（ASCII）版本：

```
P3
2 1
255
255 0 0  0 0 255
```

## 不在范围内

P7（PAM）格式的头部结构完全不同（`WIDTH`/`HEIGHT`/`DEPTH`/`MAXVAL`/`TUPLTYPE` 具名字段 + `ENDHDR`），本项目不支持。`canDecode` 只认 P1–P6。
